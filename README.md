# Kafka sine graph POC

A local Kafka proof of concept that publishes points for `y = sin(2*x) + 1`
and displays the consumed values in a live browser chart.

```text
sine-publisher -> Kafka topic: sine_graph -> sine-web -> browser (SSE)
                          |
                       Kafka UI
```

## Requirements

- Docker with Docker Compose.
- On macOS, start Docker Desktop or Colima before running the commands below.
- Available host ports: `9092`, `8080`, and `8000`.

## Start

```bash
docker compose up -d --build
docker compose ps
```

Kafka runs as a single broker/controller in KRaft mode, without ZooKeeper.
The publisher and web consumer wait for Kafka's health check before starting.
The `sine_graph` topic is automatically created on first use.

| Service | Purpose | Address |
| --- | --- | --- |
| `kafka` | Kafka broker with persistent storage | Host: `127.0.0.1:9092`; Compose network: `kafka:29092` |
| `kafka-ui` | Inspect topics, messages, and consumer groups | http://localhost:8080 |
| `sine-publisher` | Publish JSON points using its own Python image | Kafka topic `sine_graph` |
| `sine-web` | Consume points and serve a live chart using its own Python image | http://localhost:8000 |

Open the chart and allow a few seconds for new points to arrive. The browser
keeps the most recent 200 points and plots their `y` values in arrival order.
The displayed `x` value comes from the message; horizontal spacing is by sample,
not by the numeric `x` coordinate. No sine values are generated by the web UI.

## Configuration

Edit service environment values in [docker-compose.yml](./docker-compose.yml).

| Variable | Service | Default | Description |
| --- | --- | --- | --- |
| `KAFKA_BOOTSTRAP_SERVERS` | Both Python services | `kafka:29092` | Kafka bootstrap address |
| `KAFKA_TOPIC` | Both Python services | `sine_graph` | Topic to publish or consume |
| `PUBLISH_INTERVAL_MS` | `sine-publisher` | `100` | Nonnegative integer delay in milliseconds after each acknowledged send; `0` disables the intentional delay |
| `KAFKA_GROUP_ID` | `sine-web` | `sine-web` | Consumer group name |
| `PORT` | `sine-web` | `8000` | HTTP port inside the container; update the Compose port mapping if changed |

For example, set `PUBLISH_INTERVAL_MS: "500"` and apply it:

```bash
docker compose up -d sine-publisher
```

The delay does not include Kafka acknowledgement time, so `100` ms produces
slightly fewer than 10 messages per second. The publisher cycles through 64
samples over `[0, 2*pi)` and resets its sample position when restarted.

The web container is limited to `0.5` CPU via Compose's
`deploy.resources.limits.cpus` setting.

After source changes, rebuild the affected service:

```bash
docker compose up -d --build sine-publisher
docker compose up -d --build sine-web
```

## Message format

Each UTF-8 JSON message contains 17 fields:

| Fields | JSON type | Meaning |
| --- | --- | --- |
| `x`, `y` | Number | Graph coordinates rounded to six decimal places |
| `message_id`, `publisher_id` | String | UUID per message and per publisher process |
| `publisher_started_at`, `published_at` | String | UTC ISO 8601 timestamps |
| `x_decimal`, `y_decimal` | String | Coordinates formatted to six decimal places |
| `amplitude`, `angular_frequency`, `vertical_offset` | String | Fixed-point formula parameters: `1.000000`, `2.000000`, `1.000000` |
| `source`, `signal`, `formula` | String | Publisher and formula metadata |
| `x_unit`, `y_unit`, `schema_version` | String | Units and schema version |

The web server forwards the message via Server-Sent Events at `/events`.
The chart only uses `x` and `y`; the additional fields do not change rendering.
Publisher logs show the coordinates, not the complete enriched message.

## Inspect and monitor

```bash
# Follow application logs
docker compose logs -f sine-publisher sine-web

# Read actual messages, including metadata (Ctrl+C to stop)
docker compose exec kafka /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server kafka:29092 --topic sine_graph --from-beginning

# Inspect topic partitions
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server kafka:29092 --describe --topic sine_graph

# Inspect consumer offsets and lag
docker compose exec kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server kafka:29092 --describe --group sine-web

# Watch CPU and memory usage for this stack
docker compose stats
```

Consumer lag is the difference between the topic's log-end offset and the
group's committed offset. Automatic commits occur approximately every five
seconds by default, so reported lag can rise between commits even while points
are being consumed. It does not measure browser rendering delay.

The web consumer resumes from committed offsets after a restart. Without a
committed offset it starts at the latest position. Browsers receive only events
forwarded while connected; the web server does not replay history to new tabs.

Keep the topic at one partition if arrival order matters to the chart. Kafka
preserves order within a partition, not across multiple partitions.
`KAFKA_NUM_PARTITIONS` sets the default for new topics; it does not alter an
existing topic.

## Stop or reset

```bash
# Stop and remove containers, keeping Kafka data
docker compose down

# Destructive: also delete this stack's Kafka data volume
docker compose down -v
```

## POC limitations

- Plaintext Kafka and unauthenticated web interfaces; do not expose this stack
  to untrusted networks. Published ports are not restricted to host loopback.
- One broker and replication factor one: this is not a highly available setup.
- Kafka images use `latest`, and Python dependencies use a version range, so
  future builds may pull different versions.
- The web server is a simple Python HTTP server, not a production deployment.
  Slow browser clients can lose points when their 1,000-message queue fills.
- The chart is best-effort live visualization, not durable end-to-end delivery.
  Kafka offset commits do not confirm browser receipt.
